# FeedShield Hardware Adapter Architecture

This document defines the hardware abstraction layer, adapter interfaces, simulated drivers, and Web Bluetooth / serial integration protocols per **CLAUDE.md Section 0.9 & 0.10**.

---

## 1. Hardware Abstraction Philosophy

To prevent application code from becoming tightly coupled to specific physical sensors or proprietary firmware:
1. **Strict Interface Decoupling:** The UI and business logic interact exclusively with abstract TypeScript interfaces.
2. **Simulation-First Guarantee:** In the absence of physical benchtop hardware, high-fidelity simulated adapters provide realistic telemetry, noise, calibration steps, and error conditions.
3. **Honest Badging:** Every simulated measurement carries `data_provenance: "simulated_sensor"` and displays a visible **SIMULATED / DEMO** badge in the UI.
4. **Hardware Safety Notice:** Web Bluetooth and Serial drivers for physical instruments are marked: *"Untested with physical hardware — prototype integration protocol"*.

## 2. Core Hardware Adapter Interfaces (TypeScript)

```typescript
// apps/web/lib/hardware/types.ts

export interface DeviceMetadata {
  id: string;
  name: string;
  manufacturer: string;
  firmwareVersion: string;
  isSimulated: boolean;
  batteryLevel?: number;
  connectionStatus: 'connected' | 'disconnected' | 'connecting' | 'error';
}

export interface SpectrumReading {
  wavelengths: number[];        // e.g. 900 to 1700 nm
  reflectance: number[];        // 0.0 to 1.0
  darkReferenceTaken: boolean;
  whiteReferenceTaken: boolean;
  integrationTimeMs: number;
  temperatureCelsius: number;
  timestamp: string;
}

export interface NirDevice {
  getMetadata(): Promise<DeviceMetadata>;
  connect(): Promise<boolean>;
  disconnect(): Promise<void>;
  takeDarkReference(): Promise<boolean>;
  takeWhiteReference(): Promise<boolean>;
  acquireSpectrum(replicates?: number): Promise<SpectrumReading>;
}

export interface PhProbeReading {
  ph: number;
  temperatureCompensationC: number;
  millivolts: number;
  isCalibrated: boolean;
  timestamp: string;
}

export interface PhProbe {
  getMetadata(): Promise<DeviceMetadata>;
  connect(): Promise<boolean>;
  disconnect(): Promise<void>;
  readPh(): Promise<PhProbeReading>;
  calibrate(bufferPh: 4.0 | 7.0 | 10.0): Promise<boolean>;
}

export interface TempProbeReading {
  internalTempC: number;
  ambientTempC: number;
  tempDifferentialC: number;
  timestamp: string;
}

export interface TempProbe {
  getMetadata(): Promise<DeviceMetadata>;
  connect(): Promise<boolean>;
  readTemperature(): Promise<TempProbeReading>;
}

export interface GasSensorReading {
  o2Percent?: number;
  co2Percent?: number;
  ambientHumidityPercent?: number;
  timestamp: string;
}

export interface GasSensor {
  getMetadata(): Promise<DeviceMetadata>;
  connect(): Promise<boolean>;
  readGases(): Promise<GasSensorReading>;
}

export interface AssayScanResult {
  cardDetected: boolean;
  lightingQualityScore: number;
  colorReadingsLab: Array<{ padName: string; L: number; a: number; b: number }>;
  qualitativeClass: 'negative' | 'suspect_positive' | 'invalid_retake';
  confidence: number;
}

export interface AssayReader {
  validateReferenceCard(imageData: ImageData): Promise<boolean>;
  processAssayImage(imageData: ImageData, assayType: 'urea' | 'ph' | 'aflatoxin'): Promise<AssayScanResult>;
}
```

## 3. Simulated Implementations

FeedShield provides simulated drivers out-of-the-box:
* `SimulatedNirDevice`: Emits realistic 401-band spectra generated by physical equations (water absorption doublet at 1450 nm, protein N-H bands at 1510 nm, scatter baseline tilt).
* `SimulatedPhProbe`: Emits pH readings with realistic sensor drift (±0.05 pH) and temperature compensation.
* `SimulatedTempProbe`: Reads from pit telemetry profiles (healthy silage ~25–30°C vs aerobic heating ~42–55°C).
* `SimulatedAssayReader`: Generates CIELAB matches and replicates illumination test failures when reference cards are tilted or poorly lit.
